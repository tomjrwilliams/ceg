  Strat — yes, Container can become nested typed objects

  The pattern in strat/params.py:
  
  # Strategy.bind_spec(univ):
  spec = Combination(key=...)
  spec, univ = spec.with_objects(univ, rx=asset.rx())     # univ.objects += rx;  spec.refs["rx"] = "obj_N"
  spec, univ = spec.with_objects(univ, px=asset.px())     # …
  spec, univ = spec.with_objects(univ, gross=asset.gross())
  # signal/scale/cap added similarly via params.bind(...)
  univ, spec = univ.with_comb(spec)                       # univ.comb += spec
  # Then: DailyBtUvar.new(univ, spec)                     # bt → univ + comb_index

  That whole flow is "give the strategy a typed bag of named refs to its data objects". The Combination.refs: {"rx": "obj_3", 
  "px": "obj_5", …} is a poor man's typed-fields-on-an-object. Confirmed: in the post-step-5 model this collapses to:

  @dataclass(frozen=True)
  class Strategy(Object):
      parent: Basket | Strategies | str
      asset:  AssetConcrete | AssetSynthetic
      rx:     Ref
      px:     Ref
      gross:  Ref
      signal: Ref | None = None
      scale:  Ref | None = None
      cap:    Ref | None = None
      params: StrategyParams = ...

  Each Strategy is its own namespace (slot fields hold Refs). Adding the rx/px/gross/signal/scale objects to the graph happens
  through graph.with_nested(strategy, "rx", ...) etc. The Strategies container stays only as Basket-like parent — its members: 
  tuple[Ref, ...] holds Strategy refs. Combination and univ.comb/univ.agg/univ.params interning go away.
  
  Strategies.rxs: frozendict[TAsset, int] (the per-asset index map) is just a reverse lookup — replace with frozendict[TAsset, 
  IdRef] or drop entirely once strategies are first-class members.
